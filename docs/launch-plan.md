# CodeTrace 码迹 · 开源发布与冷启动计划

> 目标：**90 天 500 Star**（拆解：第 1 个月 200+，第 3 个月 500）。本项目的特殊之处在于——它的目标用户不是程序员，而是**高校教师与教务**，所以推广渠道与鉴安/轻语不同。
>
> **时间基准**：本计划的 D1 = 首次公开推送的当天。

---

## 一、发布前必须就位（Day -7 ~ Day 0）

- [ ] 仓库不含任何内部材料（竞赛方案、商业计划、学生数据均在本仓库之外）。
- [ ] README 首屏说清三件事：①评价对象是过程不是文本；②不输出二元判定；③只看证据片段、不高亮全篇。
- [ ] 演示视频（3 分钟）已录好，链接在首屏。
- [ ] `LICENSE` / `CONTRIBUTING.md` / `CITATION.cff` / CI 全绿。
- [ ] 一键可复现：`python scripts/run_demo.py`（零依赖）必须在别人的机器上也能一次跑通。
- [ ] Topics：`programming-education` `academic-integrity` `education-technology` `code-analysis` `plagiarism-detection` `python` `process-mining`。

## 二、90 天节奏

### 第 1 周：面向"技术圈里的老师"（目标 60 Star）

| 天 | 动作 | 要点 |
|---|---|---|
| D1 | 发布 v0.1.0 Release | Release Notes 附四个剧本的真实输出截图 |
| D1–2 | 发 V2EX `程序员` + `分享创造` | 标题：`我们用"代码怎么产生的"而不是"长什么样"来判编程作业，做了个零依赖原型` |
| D3 | 发 掘金 / 知乎 | 文章：《为什么代码抄袭检测该看过程，而不是看文本》 |
| D4 | 发 Bilibili | 3 分钟演示：剧本 4（局部 AI 补全只高亮局部）是核心看点 |
| D5–7 | 回复 Issue | 把高频质疑写进 FAQ |

### 第 2–4 周：教育社区渗透（目标 150 Star）

- 在**高校计算机教改**相关社群（如中国计算机教育大会相关群、CSDN 教育专栏）介绍"过程性评价"的做法；
- 写 2 篇技术文章：
  1. 《Zhang-Shasha 树编辑距离在代码演化上的分层降级实现》——纯 Python 自研；
  2. 《可离线校验的防篡改证据包是怎么做的》——链式摘要 + 增量默克尔。
- 把 `data/samples/` 的四个样例事件文件做成可下载的"教学演示包"。

### 第 2 个月：共建与真实数据（目标 300 Star）

- **最重要**：公开征集参与"30 人 × 6 题 × 3 方式"对照数据采集的学校。这是本项目最大的落地缺口，也是最能带来真实 Star 的动作（老师愿意为一个真能用的工具点 Star）。
- 接 tree-sitter，支持 Java / C / C++（接口不变），发 v0.2.0。
- 发起"**通道贡献计划**"：社区可提交新通道（附阈值标定方法）。

### 第 3 个月：破圈（目标 500 Star）

- 面向教学管理者做一次线上分享：《过程性评价能解决什么问题，不能解决什么问题》（**讲清边界比讲优势更能建立信任**）；
- 把"证据包离线校验"抽成独立小工具，方便其他教育系统复用。

## 三、本项目特有的三条推广纪律

1. **不宣传"抓作弊"**。一旦被打上"监控学生"的标签，教师社群会立刻警惕。正确的说法是"**保护诚信学生不被误判**"——FPR 是第一指标，这是产品的立身之本。
2. **主动讲局限**。答辩与发帖都要主动说"逐字重敲不可检出""数据集是合成的""能力画像模块仍在原型阶段"。**主动说局限比被追问出来好得多。**
3. **不碰隐私红线**。任何宣传材料都要强调"不采集代码全文、学生可见、可删除、不做自动化处分"。

---

## 四、不做的推广

- 不刷 Star、不买榜；
- 不公开任何学生的真实编程行为数据；
- 不把模拟结果包装成"实测检出率 99%"——一旦被验证为假，教育圈的信任不可挽回。
